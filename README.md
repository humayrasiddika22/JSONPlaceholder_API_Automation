# JSONPlaceholder API Automation

API automation testing project using Postman and Newman to validate REST API functionality, response data, request chaining, dynamic test data and automated test execution.

## Project Overview

This project demonstrates API automation testing using the JSONPlaceholder REST API. The automation covers user retrieval, dynamic user selection, specific user validation and user update operations.

## Objectives

- Automate REST API test scenarios using Postman
- Validate HTTP response status codes
- Validate response structure and data
- Implement dynamic test data
- Demonstrate request chaining
- Use environment variables
- Execute automated tests using Newman
- Generate HTML test execution reports

## How to Run

### Run in Postman

1. Import the Postman collection.
2. Import the environment file.
3. Select the environment.
4. Open the collection.
5. Run the collection using Collection Runner.

### Run with Newman

```bash
newman run collection/JSONPlaceholder_API_Automation.postman_collection.json -e environment/JSONPlaceholder_API_Automation_env.postman_environment.json
```

### Run Multiple Iterations

To execute the collection multiple times:

```bash
newman run collection/JSONPlaceholder_API_Automation.postman_collection.json -e environment/JSONPlaceholder_API_Automation_env.postman_environment.json -n 2
```

### Generate HTML Test Report

To execute the collection and generate an HTML report:

```bash
newman run collection/JSONPlaceholder_API_Automation.postman_collection.json -e environment/JSONPlaceholder_API_Automation_env.postman_environment.json -n 2 -r cli,html --reporter-html-export reports/NewmanReport.html
```

The generated `NewmanReport.html` file contains the test execution details, including requests, assertions, response times and failures.

## Environment Variables

The automation uses Postman environment variables to store and reuse data between requests.

| Variable | Purpose |
| --------------------------- | ------------------------------------------ |
| `BaseUrl` | Base URL of the JSONPlaceholder API |
| `User_id` | ID of the dynamically selected user |
| `User_name` | Name of the selected user |
| `User_email` | Email of the selected user |
| `User_company_name` | Company name of the selected user |
| `User_phone` | Phone number of the selected user |
| `updated_User_name` | Dynamically generated updated user name |
| `updated_User_email` | Dynamically generated updated user email |
| `updated_User_company_name` | Dynamically generated updated company name |

These variables allow data generated during one request to be reused in subsequent requests.

## Key Automation Features

### Request Chaining

The collection demonstrates request chaining by passing data from one request to another.

```text
GET All Users
      ↓
Select Random User
      ↓
Store User ID
      ↓
GET Specific User
      ↓
PUT Update User
```

The selected user's ID and other information are stored in environment variables and reused by subsequent requests.

### Dynamic Test Data

The update request generates dynamic values during execution instead of relying entirely on fixed test data. This allows the automation to execute the update scenario with different values across multiple runs.

### Automated Assertions

Postman test scripts are used to validate:

* HTTP status codes
* Response structure
* Required fields
* User ID consistency
* User information
* Updated user information
* Response data integrity

## API Under Test

This project uses **JSONPlaceholder**, a free fake REST API designed for testing and prototyping.

**Base URL:**
```text
https://jsonplaceholder.typicode.com
```

The current automation focuses on the `/users` resource.

## API Limitations

JSONPlaceholder is a mock API intended for testing and prototyping. Therefore, this project focuses on API automation concepts such as:

* Request and response validation
* Status code validation
* JavaScript assertions
* Dynamic test data
* Environment variables
* Request chaining
* Automated test execution
* Test reporting

It does not attempt to demonstrate production-level authentication, database persistence, payment processing or real-world business rules.
